How it works

The undergraduate version — three ideas and one formula.

1. Break it into subproblems

Aligning two whole sequences looks hard, but the best alignment of the first i bases of A with the first j bases of B only depends on three smaller answers: align one fewer base from both, from A only, or from B only. Dynamic programming just means: solve the tiny problems first, store every answer in a table, and build up. That table is the matrix above.

2. Score every choice

Each cell takes the best of three moves — diagonal (pair the two bases: match bonus or mismatch penalty), up (a base of A opposite a gap), or left (a gap opposite a base of B). The first row and column are pure gaps, so they simply accumulate the gap penalty. Change the scoring above and the “best” alignment can change with it.

3. Trace the path back

The bottom-right cell holds the optimal score, but not the alignment itself. While filling, each cell remembers which neighbor it came from. Starting at the bottom-right and following those arrows back to the top-left corner spells out the alignment: diagonal steps pair two bases, up/left steps insert a gap. Ties here are broken diagonal → up → left.

The recurrence — the whole algorithm in one line F(i, j) = max {  F(i−1, j−1) + score(A[i], B[j]),  F(i−1, j) + gap,  F(i, j−1) + gap  }

In the code, the algorithm lives in three pure functions you can test on their own: buildScoringMatrix fills the table and records where each cell came from, traceback walks the arrows back into two aligned strings, and formatAlignment turns those strings into the color-coded display, percent identity, and gap count. Cost: O(n × m) time and memory — the reason for the 200-base cap.
